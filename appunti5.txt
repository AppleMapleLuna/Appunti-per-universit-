CICLO DI DEBUG

TEST - Protegge la regressione

Unit test (integration test ) verifica una piccola unità
- veloce (feedback frequente)
- isolato (causa localizzabile)
- deterministico (stesso input, stesso esito)
TESTING 

Caso, suite e runner 
test case → scenario + aspettativa
test suite → insieme organizzato
test runner → esegue e riporta 

In python questo è facile specialmente all'esame 
FARE QUESTO.

Fare una classe per testing 
TestCase
```
import unittest 

class TestSomma(unittest.TestCase):
    def test_due_interi(self):
        risultato = 2+3
        self.assertEqual(risultato,5)

if __name__ == "__main__":
    unittest.main()
```

Differenza tra errori e fallimenti: fallimento = errore di esecuzione  all'interno al codice di test 

crea una cartella chiamata test_suite 
python di default usa il path locale. Quando il codice fa l'import di debug main va là.

Ogni volta che qualcuno fa un push su github, lancia tutti i casi di test, passa? accetta, se no no.
Sembra qualcosa di interessante.
Non importa quello che si fa, per rendere le modifiche permanente il test deve passare.

LA DISCOVERY TROVA FILE E METODI PER CONVENZIONE
python -m unittest discover
python -m unittest -b 
python -m unittest tests.test_calcoli(ecc.)

La presenza di test non garantisce che il codice sia corretta, ma fa la detection degli errori.
Se i test passano, non vuol dire che il programma o il software sia corretto.
